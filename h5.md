# [h5 It's Alive!](https://terokarvinen.com/application-hacking/#h5-its-alive-lari)

Tässä tehtävässä harjoitellaan GNU Debuggerin käyttöä.

## x) main.cpp

Ladataan main.cpp (Kurssin Moodle -sivulta). Se ilmestyy kotihakemistoon Downloads -kansioon.

    cd Downloads

    ls Downloads

Katsotaan ensin, miltä koodi näyttää microlla.

    micro main.cpp

Micro usein ilmoittaa helposti havaittavista virheistä. Tässä niitä ei näy ollenkaan.

<img width="527" height="1006" alt="image" src="https://github.com/user-attachments/assets/7b9f82d2-7693-4151-9b9a-03408edd2ae1" />

Ohjelman perusidea on siis se, että käyttäjältä pyydetään jokin luku, jonka kertoma (factorial eli n!) lasketaan ja tulostetaan.

Käännetään ohjelma ajettavaan muotoon ja testataan sen toimintaa. Koodi on kirjoitettu C++ -kielellä, joten käytetään siihen tarkoitettua kääntäjää. Annetaan ajettavalle ohjelmalle nimeksi main.

        g++ main.cpp -o main

Ajetaan ohjelma.

        ./main

Ohjelma näyttäisi palauttavan aina vain nollan riippumatta syötteeseen laitettavasta numerosta, vaikka sen pitäisi palauttaa syötteen kertoma.

<img width="587" height="291" alt="image" src="https://github.com/user-attachments/assets/85dd9b57-5c1c-4c41-be63-8f45141efc15" />

Käännetään ohjelma ajettavaan muotoon siten, että sitä voi tarkastella GNU Debuggerilla.

    g++ main.cpp -g -o main-dbg

- g++ kääntää ohjelman C+ -kielestä koneelle ymmärrettävään muotoon.
- -g kääntää ohjelman siten, että sitä voi tarkastella GNU Debuggerilla.
- -o tallentaa tämän käännetyn tiedoston halutulla nimellä.

ls -komennolla nähdään, että main-dbg tiedosto ilmestyi.

Asennetaan GNU Debugger.

    sudo apt-get update

    sudo apt-get install gdb

Käynnistetään gdb.

    gdb ./main-dbg

gdb avautuu onnistuneesti.

<img width="1376" height="727" alt="image" src="https://github.com/user-attachments/assets/2b7d9b31-3965-4e2d-926f-b300f1d76d84" />

Komentoriville ilmestyy teksti (gdb), mikä tarkoittaa, että GNU Debuggerille voi syöttää komentoja.

Tuli ilmoitus, että ohjelma suoritettiin onnistuneesti, mutta siltä ei kuitenkaan tullut toivottua tulostusta.

Laitetaan breakpoint heti ohjelman alkuun, käynnistetään se ja käydään sitä läpi rivi kerrallaan ohjelman mukaisessa järjestyksessä.

    break main

    run

    step

    // step voidaan lyhentää komentorivillä s

<img width="462" height="168" alt="image" src="https://github.com/user-attachments/assets/3e117285-875c-4849-b6ed-a96caecd7213" />

cin>>n; -kohdassa kysytään käyttäjältä syötettä, joten laitetaan syötteeksi 5.

Rivillä 11 main -funktiosta siirrytään factorial -funktioon. step -komennon avulla päästään tarkastelemaan ohjelmaa rivi kerrallaan ohjelman suoritusjärjestyksessä, 
kun taas next -komennolla mentäisiin vain rivi kerrallaan eteenpäin.

print -komennolla voidaan tulostaa jonkin muuttujan sen hetkinen arvo.

        print n

        print result

n -muuttujan arvoksi saadaan 5, eli se mikä pistettiin syötteeksi. result -muuttujan arvoksi saadaan 1, joka on aina ensimmäisen loopin arvo, koska se on määritelty niin rivillä 19 (long result(1)).

<img width="329" height="162" alt="image" src="https://github.com/user-attachments/assets/435d84c8-2cf7-4937-a9eb-70726d01de0b" />

watch n -komenolla saadaan tarkkailtua n -muuttujan arvoa. gdb ilmoittaa, kun sen arvo muuttuu.

        watch n

<img width="443" height="168" alt="image" src="https://github.com/user-attachments/assets/7200473d-68ad-41e4-b7cb-26ab5242c1e8" />

Käydään seuraavaksi factorial -funktion while -looppi kokonaan läpi ja katsotaan result -muuttujan arvo jokaisella n -muuttujan arvolla.

Kun n -muuttujan arvo on vaihtunut, edetään funktiossa **step (s)** -komennolla eteenpäin ja katsotaan result -muuttujan arvo while(n--) -rivin jälkeen **print result** -komennolla.

<img width="932" height="428" alt="image" src="https://github.com/user-attachments/assets/cb070d21-fa68-4088-ba1c-393f7511534b" />

Taulukko tuloksista:

| n | result |
|---|--------|
| 5 | 1      |
| 4 | 4      |
| 3 | 12     |
| 2 | 24     |
| 1 | 24     |
| 0 | 0      |
|-1 | 0      |

result -muuttujan arvo siis kasvaa, kunnes n -muuttujan arvo on 2. result putoaa nollaan, koska n -muuttujan arvo menee nollaan, vaikka ei pitäisi, jos kertoma halutaan saada selville. 

n -muuttujan arvoa pienennetään ennen kuin se on kerrottu result -muuttujan kanssa, minkä takia ohjelman logiikka ei toimi kuten olisi toivottu.
